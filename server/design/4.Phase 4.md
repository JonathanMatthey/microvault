# Phase 4 — Download, Listing, and Egress Charging

## Purpose

Phase 4 introduces **file listing**, **download**, and **deletion** capabilities to the client, completing the core upload-download-accounting cycle. Downloads are charged via the **egress rate** defined in Phase 1, with credits deducted per successfully streamed chunk (16 MiB). File deletion is **free** and removes the file from storage immediately.

This phase keeps all Phase 2-3 functionality intact (uploads, Web Monetization) and adds the ability to retrieve and manage previously uploaded files.

The outcome of this phase is:
- Users can list their uploaded files via a directory interface.
- Users can download files and are charged per successfully streamed chunk.
- Users can delete files to free up storage space.
- Frozen accounts cannot download (server-enforced) but can list and delete files.
- Downloaded bytes are correctly tracked and charged using the egress rate.
- All data remains segregated per user via the existing `userHash` mechanism.

## Architecture Changes

### 1. Backend File Listing

**Endpoint: `GET /files` (auth required)**

Returns a JSON array of all files uploaded by the authenticated user:

```json
[
  {
    "id": "upload-id-123",
    "filename": "document.pdf",
    "size": 5242880,
    "createdAt": "2025-12-17T10:30:00Z",
    "uploadedAt": "2025-12-17T10:32:15Z",
    "estimatedDownloadCost": 156
  },
  {
    "id": "upload-id-456",
    "filename": "archive.tar.gz",
    "size": 104857600,
    "createdAt": "2025-12-17T11:00:00Z",
    "uploadedAt": "2025-12-17T11:15:30Z",
    "estimatedDownloadCost": 1560
  }
]
```

**Implementation:**
- Query tusd's `.info` metadata files for the user's uploads.
- Parse file size from metadata.
- Calculate estimated download cost: `ceil(size / 16MiB) * EgressCreditsPerChunk`.
- Sort by uploadedAt (newest first).
- Filter to only files marked as complete (tusd status).

### 2. Backend File Download

**Endpoint: `GET /files/<uploadID>/download` (auth required)**

Streams the file in 16 MiB chunks. Credits are deducted **only for successfully streamed chunks**.

**Pre-download checks (FR4.2 - Frozen Blocks Download Start):**
1. Extract user ID from authentication.
2. Query ledger for current balance.
3. Check policy: `CanDownload(balance)` → must not be frozen.
4. If frozen → reject with 402 Payment Required.
5. If allowed → proceed to stream.

**Per-chunk egress charging (FR4.3 - Egress Deduction):**
- File is read from storage in 16 MiB chunks.
- Each chunk is sent to client via HTTP response body.
- **After successful chunk write to response** → debit credits using egress rate.
- **Do NOT charge for unwritten/failed chunks** (e.g., client disconnects mid-stream).
- Log each deduction for debugging and audit trail.

**Stream response:**
```
Content-Type: application/octet-stream
Content-Length: <file-size>
Content-Disposition: attachment; filename="<original-filename>"

[binary file data streamed in 16 MiB chunks]
```

**Error responses:**
- 404: Upload ID not found or belongs to different user.
- 402: Account frozen or insufficient balance.
- 401: Missing or invalid authentication.

---

### 3. Egress Rate Constant

**From Phase 1 design:**
```go
EgressRatePerGiB = 8.0  // credits per GiB
```

**Calculate egress cost per 16 MiB chunk:**
```go
EgressCreditsPerChunk = (EgressRatePerGiB * 16MiB) / (1 GiB)
                      = (8.0 * 16 MiB) / 1024 MiB
                      = 0.125 credits per chunk
                      = 1250 internal units (scale 4)
```

**Implementation in `internal/core/constants.go`:**
```go
const (
    EgressRatePerGiB int64 = 8 * CreditUnit  // 8.0 credits
    EgressCreditsPerChunk = (EgressRatePerGiB * ChunkSizeBytes) / (1024 * 1024 * 1024)
                          = 1250
)
```

### 4. Backend File Deletion

**Endpoint: `DELETE /files/<uploadID>` (auth required)**

Deletes a file from storage immediately and permanently.

**Pre-deletion checks:**
1. Extract user ID from authentication.
2. Verify the upload ID belongs to this user.
3. If not found or belongs to different user → 404.
4. If found → delete file and metadata immediately.

**Response (200):**
```json
{
  "message": "file deleted",
  "id": "upload-id-123",
  "freedBytes": 5242880
}
```

**Error responses:**
- 404: Upload ID not found or belongs to different user.
- 401: Missing or invalid authentication.

**Implementation notes:**
- Deletion is **free** (no charge, no ledger impact).
- Frozen accounts **can delete** (no policy restriction).
- Delete tusd upload file and corresponding `.info` metadata file.
- Log deletion for audit trail.
- Update storage accounting for daily billing (Phase 5 may use this).

### 5. Download Handler Implementation

**File: `internal/upload/download.go`**

```go
package upload

import (
    "context"
    "io"
    "net/http"
)

// DownloadHandler serves user files in chunks, deducting credits per chunk.
type DownloadHandler struct {
    dataRoot   string
    ledger     ledger.Ledger
    policy     policy.Engine
    service    *Service
}

// Download streams file to client, deducting credits per successful chunk.
func (h *DownloadHandler) Download(c echo.Context) error {
    userID := extractUserID(c)
    uploadID := c.Param("uploadID")
    
    // Pre-download checks
    if !h.policy.CanDownload(h.ledger.Balance(userID)) {
        return c.JSON(http.StatusPaymentRequired, map[string]string{
            "error": "account frozen or insufficient balance",
        })
    }
    
    // Resolve file path
    filePath := filepath.Join(h.dataRoot, userHash(userID), uploadID)
    file, err := os.Open(filePath)
    if err != nil {
        return c.JSON(http.StatusNotFound, map[string]string{"error": "file not found"})
    }
    defer file.Close()
    
    // Get file size and metadata
    fileInfo, _ := file.Stat()
    fileName := extractFileNameFromMetadata(uploadID, h.dataRoot, userID)
    
    // Set response headers
    c.Response().Header().Set("Content-Type", "application/octet-stream")
    c.Response().Header().Set("Content-Length", fmt.Sprintf("%d", fileInfo.Size()))
    c.Response().Header().Set("Content-Disposition", fmt.Sprintf("attachment; filename=\"%s\"", fileName))
    
    // Stream in 16 MiB chunks, deducting credits per chunk
    buffer := make([]byte, ChunkSizeBytes)
    for {
        n, err := file.Read(buffer)
        if n > 0 {
            // Write chunk to response
            if _, wErr := c.Response().Write(buffer[:n]); wErr != nil {
                // Client disconnected; stop charging
                return nil
            }
            
            // Deduct credits for successfully written chunk
            if err := h.ledger.Debit(userID, EgressCreditsPerChunk); err != nil {
                // Log but don't fail; continue streaming
                log.Printf("[download] debit failed user=%s err=%v", userID, err)
            }
        }
        if err == io.EOF {
            break
        }
        if err != nil {
            return c.JSON(http.StatusInternalServerError, map[string]string{
                "error": "read error",
            })
        }
    }
    
    return nil
}
```

---

### 6. Frontend Download Flow

**Steps:**
1. User clicks "Download" on a file.
2. Frontend shows cost confirmation dialog: `"This download will cost ~XXX credits. Continue?"`.
3. User confirms.
4. Frontend initiates HTTP GET to `/files/<uploadID>/download`.
5. Browser handles streaming (native download) or fetch API with progress tracking.
6. Display progress bar showing bytes/chunks downloaded.
7. On completion, show success message and refresh balance.
8. On error (402, 404, etc.), show appropriate error message.

**Error handling:**
- If account becomes frozen mid-download, subsequent chunks will fail (server blocks).
- Display message: `"Download interrupted: account frozen."`.
- Allow user to credit account and retry.

Stream file to client, deducting credits per successfully streamed chunk.

Content-Type: application/octet-stream

## Test-Driven Development Requirements

### T4.1 — Download Start Authorization

- **Given** a user is Frozen
- **When** attempting to start a download
- **Then** the request must fail with 402 Payment Required
- **And** no chunks are streamed or charged

- **Given** a user is Active
- **When** attempting to start a download
- **Then** the request must succeed
- **And** the file is streamed

### T4.2 — Per-Chunk Egress Charging

- **Given** a user downloads a file of size N bytes
- **When** all N bytes are successfully streamed
- **Then** exactly `ceil(N / 16MiB) * EgressCreditsPerChunk` credits must be deducted
- **And** balance is reduced accordingly

### T4.3 — No Charge on Failed Stream

- **Given** a download is interrupted (client disconnects)
- **When** only M of N bytes have been streamed
- **Then** only `ceil(M / 16MiB) * EgressCreditsPerChunk` credits must be deducted
- **And** remaining bytes are not charged

### T4.4 — File Listing Correctness

- **Given** a user has uploaded multiple files
- **When** calling GET `/files`
- **Then** all files are returned with correct metadata (name, size, date)
- **And** estimated download cost is calculated correctly per file

### T4.5 — Cross-User Isolation

- **Given** two users with different uploads
- **When** each user lists files or downloads
- **Then** each user only sees their own files
- **And** no cross-user access is possible

### T4.6 — File Deletion

- **Given** a user has uploaded a file
- **When** calling DELETE `/files/<uploadID>`
- **Then** the file must be deleted from storage
- **And** no charge occurs
- **And** subsequent GET requests for that file return 404

### T4.7 — Frozen Account Can Delete

- **Given** a user account is Frozen
- **When** attempting to delete a file
- **Then** the request must succeed
- **And** the file is deleted immediately
- **And** no charge occurs

## Notes

- **File deletion is free** - No charge, no ledger impact, no policy restriction
- **Frozen accounts can delete** - Allows users to free up storage space
- **Permanent deletion** - No recycle bin or soft delete in Phase 4
- **Flat namespace** - No directories; only flat file listing per user
- **No compression** - Files streamed as-is
- **No sharing** - Downloads require authentication; no public links
- **Charge on write, not on read** - Credits deducted as bytes stream to client
- **Keep balances atomic** - Each chunk debit is independent; no transactions needed
- **Egress rate** - 8.0 credits per GiB (much higher than ingress)
- **16 MiB chunks** - Consistent with Phase 1-2 definition
