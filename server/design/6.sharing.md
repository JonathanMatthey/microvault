# Phase 6: Sharing Links

Goal: Allow users to generate time-limited share links for their files. Anonymous recipients can download via the link if the owner has sufficient credits; the owner pays egress on successful download.

## Requirements
- Share button per file in the UI.
- Each click creates a new link valid for 7 days. Multiple active links per file are allowed; no implicit revocation.
- Anonymous download via link is allowed if the owner account is not frozen and has enough credits for egress at request time.
- Charge egress to the owner **only after** a successful download completes.
- Expired links must be rejected. Links should be unguessable (high-entropy tokens).
- Apply basic abuse protections: rate-limit link creation, rate-limit downloads per link/IP, and cap active links per file if needed.

## Data Model
- Table/collection: `share_links`
  - `id` (UUID) — internal identifier
  - `token` (opaque, high-entropy) — used in the URL
  - `user_id`
  - `upload_id`
  - `created_at`, `expires_at`
  - `downloads` (count)
  - `last_download_at`
  - Optional: `revoked_at` for manual/admin revocation
- Indexes: token (unique), (user_id, upload_id), expires_at for cleanup.

## API Surface (proposed)
- `POST /files/:uploadId/share`
  - Auth required (owner)
  - Creates a new share link valid for 7 days
  - Returns `{ share_url, expires_at }`
- `GET /share/:token`
  - No auth required
  - Validates token, expiry, owner account state, and egress affordability
  - On success, returns a presigned download URL or streams via proxy
  - Increments download count and charges egress after successful download

## Flow: Create Link
1) Authenticated owner calls `POST /files/:uploadId/share`.
2) Validate ownership of `uploadId`.
3) Create `share_links` record with `expires_at = now + 7d`, generate opaque `token`.
4) Return full URL (`/share/{token}`) and expiry.

## Flow: Redeem Link (Download)
1) Anonymous user hits `/share/{token}`.
2) Validate token exists and not expired; ensure owner account is not frozen.
3) Check egress affordability using file size and configured `egress_per_gib`. If insufficient credits, return 402.
4) Generate presigned GET (or proxy stream if CSP requires), start download.
5) After successful download completion, deduct egress from owner and increment download count.
6) If download fails mid-transfer, do **not** charge.

## Charging Rules
- Egress cost = `CalculateEgressCost(file.size, egress_per_gib)`; charge only on success.
- Storage and ingress are unchanged; only egress is billed for shared downloads.

## Security & Abuse Controls
- Tokens: 128-bit random (Base64URL) to prevent guessing.
- Rate limits: per-user share creation (e.g., 10/min), per-token download (e.g., 20/hour/IP).
- Expiry enforcement: reject requests where `now > expires_at`.
- Optional: max active links per file (e.g., 10) to limit proliferation.
- Logging/metrics: link creation, redemption attempts, success/failure, egress charged.

## Frontend
- Add a **Share** button per file row.
- On click, call `POST /files/:uploadId/share` and display the returned link + expiry.
- Re-clicking produces a new link (do not revoke prior links).
- Show an indicator when a link is copied/created; consider a simple list of active links (optional, not required for MVP).

## Cleanup
- Background job to purge expired links (and their tokens) nightly.
- Optionally retain aggregate stats for reporting after deletion of the token.

## Open Questions / Next Steps
- Should we expose an owner view of active links for a file? (Not required for MVP.)
- Should we allow manual revocation? (If yes, add `DELETE /files/:uploadId/share/:token`.)
- Do we need per-link download caps? (Optional; can reuse rate limits.)
