# Phase 2 — Local TUS Uploads (Embedded tusd) with Credit Deduction

## Purpose

Phase 2 introduces **real uploads** using the **embedded Go tusd library**, while keeping the system fully runnable on a developer's local machine.

This phase focuses on:
- Integrating tusd (embedded) into the Go application
- Supporting authenticated uploads through the existing front-end (dev mode)
- Enforcing **account freeze rules** at upload start
- Deducting credits accurately **per successfully completed chunk**
- Storing uploaded data on the **local filesystem** via tusd's filestore

Phase 2 does **not** include daily storage snapshot billing, downloads, S3, or web monetization.

The outcome of this phase is:
- Users can upload files through a web frontend using TUS
- Credits are deducted per successfully uploaded chunk (not failed chunks)
- Frozen accounts are blocked from starting new uploads (server-enforced)
- All data is stored on local filesystem with per-user segregation
- Dev-login mode allows testing without OIDC

**Middleware flow:**
```
Request → Extract X-User-ID → Check Policy → TUS Handler → Per-Chunk Hooks → Debit Ledger
```

**Pre-upload checks (FR2.4 - Frozen Blocks Upload Start):**
1. Extract user ID from `X-User-ID` header
2. Query ledger for current balance
3. Check policy: `CanUpload(balance)`
4. If frozen or insufficient balance → reject with 402 Payment Required
5. If allowed → proceed to tusd handler

**Per-chunk accounting (FR2.5 - Credit Deduction):**
- Hook into tusd's upload progress/completion events
- Calculate chunk size (up to 16 MiB)
- **Only debit credits after chunk successfully written**
- **Do NOT charge for failed chunks**
- Do NOT use credit holds or reservations
- Log each deduction for debugging and audit trail
- Hook into tusd's upload progress events

- Log each deduction for debugging

### 3. Credit Calculation

**Constants (from design):**
```go
ChunkSize = 16 * 1024 * 1024  // 16 MiB
IngressRatePerGiB = 1.0 credits
```

**Formula:**
```go
chunks = ceil(bytes / ChunkSize)
creditsPerChunk = (IngressRatePerGiB * ChunkSize) / (1 GiB)
                = (1.0 * 16 MiB) / 1024 MiB
                = 0.015625 credits per chunk
                = 156 internal units (scale 4)
```

## Test-Driven Development Requirements

Phase 2 must be built with TDD. At minimum, implement the following tests:

### T2.1 — Upload Start Authorization
- **Given** a user is Frozen
- **When** attempting to start a new upload
- **Then** the request must fail with 402 Payment Required
- **And** no upload ID is created

- **Given** a user is Active
- **When** attempting to start a new upload
- **Then** the request must succeed
- **And** an upload ID is returned

### T2.2 — Per-Chunk Charging Correctness
- **Given** a user uploads N chunks successfully
- **When** all chunks complete
- **Then** exactly `N * CreditsPerChunk` credits must be deducted
- **And** retry of a chunk must not double-charge

### T2.3 — No Charge on Failure
- **Given** a chunk write fails or is interrupted
- **When** the chunk is not successfully written
- **Then** no debit must occur for that failed chunk
- **And** balance remains unchanged

### T2.4 — Local Filestore Persistence
- **Given** a successful upload completes
- **When** checking the filesystem
- **Then** the file must exist at `data/<userHash>/<uploadID>`
- **And** file size must match uploaded bytes
- **And** basic checksum validation passes
